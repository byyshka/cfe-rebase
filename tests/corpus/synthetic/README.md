# Синтетический корпус

Единственные данные, на которых открытый проект проверяет инструменты: выдуманная «типовая» в двух релизах, два
расширения и эталон ручного переноса. Кода типовых конфигураций 1С здесь нет: предметная область, имена и тексты
придуманы, это проверяет `scripts/check_corpus_clean.py` (ни одна строка `.bsl` длиной от 40 символов не
встречается в выгрузках УТ 11.5.22.159 и 11.5.27.79; общие для всех конфигураций строки — объявления обработчиков
событий платформы, `#Область` и чистый синтаксис — не ищутся).

Формат — как у выгрузки Конфигуратора 8.3.27 (формат 2.20): UTF-8 с BOM, CRLF, табы. Исключения сделаны нарочно
(случай J). `.gitattributes` репозитория (`* -text`) не даёт git нормализовать концы строк: править файлы только
в бинарном режиме или редактором, который сохраняет BOM и концы строк.

## Раскладка

| Папка | Что |
|---|---|
| `old/` | «типовая» `ТиповаяДемо` 11.5.22.1 |
| `new/` | она же, 11.5.27.1 |
| `ext/Синт_Основное/` | расширение «до» переноса: Адаптация, префикс `Синт_` |
| `ext/Синт_Печать/` | второе расширение (Адаптация): `&Вместо` без `ПродолжитьВызов` на метод, перехваченный первым |
| `work/Синт_Основное_11_5_27_01_10_2026_v_1_0/` | эталон ручного переноса: имя расширения и папки с датой и версией, `uuid` объекта `Configuration` тот же |
| `expected/<прогон>.json` | нормализованные JSON-отчёты инструментов (`tests/corpus/normalize.py`) |

Объекты «типовой»: `ОбщийМодуль.ЗаказыСервер` (сервер), `ОбщийМодуль.ЗаказыКлиентСервер`, `Документ.ЗаказПокупателя`
(модули объекта и менеджера, формы `ФормаДокумента` и `ФормаСписка`), `Справочник.Контрагенты`, `Номенклатура`,
`Склады`, `Перечисление.СтатусыЗаказов`, `РегистрНакопления.ТоварыНаСкладах` (остатки). `Синт_Основное` заимствует
оба общих модуля, документ и обе формы и добавляет свой общий модуль `Синт_ЗаказыСервер`.

В `work/` перенесены только методы `&ИзменениеИКонтроль`: `REBASED` — кандидатами `control_rebase` (в
`Синт_РассчитатьСуммуЗаказа` без одной пустой строки — сравнение её не видит), `CONFLICTS`, `FAIL` и оба
`OUT_OF_SYNC` — вручную под new, `MISSING` удалён вместе с методом вендора. Остальной код `work/` совпадает с `ext/`.

## Прогоны (`tests/corpus/test_synthetic.py`, `RUNS`)

| Прогон | Команда | Отчёт |
|---|---|---|
| `control_rebase` | `--ext ext --old old --new new --work work` | `report.json` |
| `control_rebase_work` | `--ext work --old old --new new` — рабочая копия после переноса | `report.json` |
| `method_diff` | `--ext ext --old old --new new` | `report.json` |
| `interceptors` | `--ext-root ext --config-old old --config-new new` (без `--order`) | `interceptors.json` |
| `calls`, `bodies`, `queries` | то же | `<команда>.json` |

Сокращения модулей ниже: ЗС — `CommonModules/ЗаказыСервер/Ext/Module.bsl`, ЗКС — `CommonModules/ЗаказыКлиентСервер/…`,
ММ — `Documents/ЗаказПокупателя/Ext/ManagerModule.bsl`, МО — `…/Ext/ObjectModule.bsl`, ФД и ФС — модули форм
`ФормаДокумента` и `ФормаСписка` (`…/Forms/<Форма>/Ext/Form/Module.bsl`, рядом `Form.xml`), СЗС —
`CommonModules/Синт_ЗаказыСервер/Ext/Module.bsl`. Расширение — `Синт_Основное`, если не сказано иное.

## Маркеры внутри текста запроса

Платформа выбрасывает строки `#Вставка`/`#КонецВставки` и блоки `#Удаление` до компиляции, поэтому строковый литерал
продолжается через них. `bsl.tokenize` делает так же: у `Синт_ТоварыЗаказа` `queries.py` читает оба текста запроса
целиком, вместе с таблицей и полями после маркера (`stats.query_tables` = 2,
`test_C_queries_reads_a_query_with_markers_inside`). В ранних версиях литерал закрывался на первом маркере, и хвост
запроса выпадал из проверки.

## Обновление expected

Только после чтения `report.md` каждого изменившегося прогона:

```
python -m tests.corpus.regen_expected            # прогнать, показать разницу и пути к report.md
python -m tests.corpus.regen_expected --write    # то же и перезаписать expected/
```

`CFE_REBASE_LEGACY_TOOLS=<папка с исходными скриптами>` и в тестах, и здесь запускает вместо пакета исходные скрипты,
из которых он собран (в репозиторий не входят), с теми же аргументами. `expected/` сняты с них и пакетом
воспроизводятся без расхождений.

## Как перегенерировать

`old/`, `new/`, `ext/` и `work/` строит генератор `tests/corpus/gen/build_corpus.py` (тексты модулей —
`bsl_texts.py`, XML — `xmlgen.py`). `work/` он собирает из кандидатов `REBASED` прогона `control-rebase` пакета по
сгенерированным выгрузкам и ручных переносов `bsl_texts.WORK_PORTS`. В эту папку генератор не пишет: закоммиченные
файлы — источник истины, а `tests/corpus/test_generator.py` проверяет, что генератор воспроизводит их побайтно (все,
кроме `expected/` и этого README, вместе со списком файлов).

```
python tests/corpus/gen/build_corpus.py --check        # собрать во временную папку и сравнить, код 1 — есть расхождения
python tests/corpus/gen/build_corpus.py --out <папка>  # записать корпус в пустую папку
```

Порядок правки:

1. Изменить генератор (`bsl_texts.py`, `build_corpus.py`), а не файлы корпуса.
2. `--out` во временную папку; прочитать `report.md` прогона `control_rebase`, из которого собран `work/` (путь
   генератор печатает последней строкой).
3. Заменить `old/`, `new/`, `ext/` и `work/` здесь папками из неё целиком (файлы копировать как есть, без
   перекодировки), затем `--check` → 0 расхождений.
4. `python -m tests.corpus.regen_expected`, прочитать `report.md` изменившихся прогонов, затем `--write` (раздел
   «Обновление expected»).
